# ❗ 0. 문제 인식

다음과 같은 CSS 작성 방식이 있다고 가정한다.

```css
.box1 {}
.box2 {}
.red-text {}
.big-text {}
```

```html
<div class="box1">
  <p class="red-text big-text">안녕하세요</p>
</div>
```
<br>

## ✍️ Q. 아래 질문에 답하시오

### 1. 클래스 이름만 보고 역할을 명확하게 알 수 있는가?

`box1`, `box2` 같은 이름만으로 해당 요소가 어떤 역할을 하는지 알아내긴 어려울 것 같다.

예를 들어 `box1`이 카드인지, 버튼 영역인지, 프로필 영역인지 알 수 없다. (너무 포괄적인 의미임)


---

### 2. 스타일 충돌이 발생할 가능성은 없는가?


여러 페이지에서 `.box1`이라는 클래스를 사용하면,  
한 곳에서 수정한 스타일이 다른 페이지에도 영향을 줄 수 있다!

또한 `.red-text`, `.big-text`처럼 스타일 속성 기반으로 이름을 지으면,  
나중에 색상이나 크기를 변경할 때 클래스 이름과 실제 스타일이 맞지 않는 문제가 생길 수도 있다!

---

### 3. 프로젝트가 커졌을 때 유지보수는 쉬울까?

유지보수가 어려울 거 같다.

프로젝트가 커질수록 CSS 파일과 클래스가 많아지는데,  
`box1`, `box2`처럼 의미가 불분명한 이름은 나중에 봤을 때 어떤 요소에 적용된 스타일인지 알기 어렵다.

결국 CSS를 수정할 때마다 HTML 구조를 계속 확인해야 하고,  
실수로 다른 부분의 디자인을 망가뜨릴 가능성도 높아진다..!

---

### 4. 이런 방식이 실무에서 문제가 되는 이유를 설명하시오

실무에서는 여러 사람이 함께 코드를 작성하고 수정하게 된다.
이때 클래스 이름이 명확하지 않으면 다른 개발자가 코드를 이해하기 어렵다.

또한 서비스 규모가 커지면 페이지와 컴포넌트가 많아지기 때문에,  
CSS 이름이 체계적으로 관리되지 않으면 중복, 충돌, 유지보수 문제가 발생하게 된다.

-> 그래서 실무에서는 CSS를 더 체계적으로 관리하기 위한 방법을 사용해야한다!

# 🧩 1. 조사 및 정리

## 1) CSS를 무작정 작성했을 때 생기는 문제

- 클래스 이름이 중복될 수 있다.
- 어떤 요소에 적용된 스타일인지 파악하기 어렵다.
- 한 곳을 수정했는데 다른 곳의 스타일이 함께 바뀔 수 있다.
- CSS 파일이 길어질수록 관리가 어려워진다.
- 협업할 때 다른 사람이 코드를 이해하기 어렵다.


---

## 2) BEM이란 무엇인가

BEM은 CSS 클래스 이름을 체계적으로 짓기 위한 방법론

BEM은 다음 세 가지 개념으로 구성

- **Block**: 독립적인 하나의 큰 영역
- **Element**: Block 안에 포함된 요소
- **Modifier**: Block 또는 Element의 상태나 변형

예시:

```html
<div class="profile-card">
  <img class="profile-card__image" src="profile.png" alt="프로필 이미지">
  <h2 class="profile-card__name">홍길동</h2>
  <p class="profile-card__description">프론트엔드 개발자를 꿈꾸고 있습니다.</p>
  <button class="profile-card__button profile-card__button--primary">
    GitHub
  </button>
</div>
```

위 코드에서:

- `profile-card`는 Block
- `profile-card__image`, `profile-card__name`은 Element
- `profile-card__button--primary`는 Modifier

BEM을 사용하면 클래스 이름만 보고도 해당 요소가 어떤 영역에 속하는지 쉽게 알 수 있다!!

---

## 3) Tailwind CSS는 어떤 방식인가

Tailwind CSS는 Utility-first 방식의 CSS 프레임워크입니다.

Utility-first란, 미리 만들어진 작은 기능 단위의 클래스를 조합해서  
HTML 안에서 직접 스타일을 작성하는 방식입니다.

예시:

```html
<div class="w-80 p-6 rounded-xl shadow-md bg-white">
  <h2 class="text-xl font-bold">홍길동</h2>
  <p class="mt-2 text-gray-600">프론트엔드 개발자를 꿈꾸고 있습니다.</p>
</div>
```

위 코드에서:

- `w-80`은 너비를 지정
- `p-6`은 padding 지정
- `rounded-xl`은 모서리를 둥글게 만들기
- `shadow-md`는 그림자를 적용
- `text-xl`은 글자 크기를 지정
-  ( sm < md < lg < xl < 2xl < 3xl ...)

Tailwind CSS는 별도의 CSS 클래스명을 많이 고민하지 않아도 되고, HTML 안에서 빠르게 UI를 만들 수 있다는 장점이 있다

(테일윈드가 알아서 별도의 css 파일을 만들고 같은 클래스명을 써도 알아서 고유한 id를 부여하는식이라네요)

# 🚀 4. 추가 도전

## 1) transition 사용

버튼과 카드에 `transition`을 사용  
hover 시 변화가 자연스럽게 일어나도록 했다! (갑자기, 바로 안 바뀜)

```html
<div class="hover:shadow-xl transition">
```

```html
<a class="hover:bg-gray-700 transition">
```


---

## 2) 반응형 스타일 적용

화면 크기가 `md` 이상일 때 카드의 최대 너비가 조금 더 커지도록 했다

```html
<div class="w-full max-w-sm md:max-w-md">
  <!--
  md:max-w-md → 화면이 md(768px) 이상일 때 최대 너비를 더 크게 적용
  모바일에서는 작게, 큰 화면에서는 더 넓게 보이도록 하는 반응형 설정
-->
  
```

이렇게 하면 모바일 화면에서는 작고,  
태블릿이나 데스크탑 화면에서는 조금 더 넓게 보인다!

# 🔍 5. 비교 및 회고

## 1) BEM 방식으로 다시 설계


```html
<body class="page">
    <div class="profile-card">
        <div class="profile-card__avatar">
            👤
        </div>

        <div class="profile-card__status">

        </div>

        <div class="profile-card__info">
            <h1 class="profile-card__name">이효빈</h1>
            <p class="profile-card__major">영어 · 컴퓨터공학 전공</p>
        </div>

        <p class="profile-card__description">
            인터랙티브 개발자를 꿈꾸고 있어요
        </p>

        <hr class="profile-card__divider">

        <div class="profile-card__tags">
            <span class="profile-card__tag profile-card__tag--blue">HTML</span>
            <span class="profile-card__tag profile-card__tag--purple">CSS</span>
            <span class="profile-card__tag profile-card__tag--yellow">JavaScript</span>
            <span class="profile-card__tag profile-card__tag--cyan">React</span>
        </div>

        <div class="profile-card__actions">
            <a href="#" class="profile-card__button profile-card__button--primary">
            GitHub
            </a>
            <a href="#" class="profile-card__button profile-card__button--secondary">
                Notion
            </a>
        </div>
    </div>
</body>
```

BEM 방식으로 작성하면 클래스 이름만 봐도 각 요소가 `profile-card` 안에 포함되어 있다는 것을 알 수 있다!

예를 들어:

- `profile-card__avatar`: 프로필 카드의 아바타 영역
- `profile-card__name`: 프로필 카드의 이름 영역
- `profile-card__tag`: 프로필 카드의 기술 태그
- `profile-card__button--primary`: 주요 버튼 스타일

## 2) Tailwind 사용 경험

### 👍 편했던 점

CSS 파일을 따로 많이 작성하지 않아도 된다는 점입니다.  
(BEM 방식으로 짠 간단한 CSS 코드만 해도 벌써 160줄이다...)

`p-6`, `rounded-2xl`, `shadow-lg`, `text-gray-600`처럼  
미리 만들어진 클래스를 조합해서 빠르게 스타일을 적용할 수 있는게 너무 편했다.

또한 hover 효과나 반응형 스타일도  
`hover:bg-gray-700`, `md:max-w-md`처럼 HTML 안에서 바로 작성할 수 있어 편리했습니다.

---

### 👎 불편했던 점

반대로 CSS 코드가 짧아지는 대신, HTML 코드가 길어진다.

특히 요소 하나에 여러 Tailwind 클래스를 작성하다 보면 코드가 길어져서 읽기가 너무 어려워진다..

또한 같은 스타일을 여러 번 반복해서 작성해야 하는 경우에는 
중복이 생길 수 있다고 생각했다.

근데 이 유틸리티 클래스들을 다 찾아봐야하는 것도 좀 불편하다.
(물론 CSS도 다 AI랑 인터넷 찾아보긴 하지만..)
---

## 3) BEM vs Tailwind 차이

| 구분 | BEM | Tailwind CSS |
| --- | --- | --- |
| 작성 방식 | 의미 있는 클래스명을 직접 설계 | 미리 정의된 유틸리티 클래스를 조합 |
| CSS 파일 | 직접 작성하는 CSS가 많음 | CSS 파일 작성이 적음 |
| 장점 | 구조와 역할이 명확함 | 빠르게 UI 구현 가능 |
| 단점 | 클래스명 설계가 필요함 | HTML 코드가 길어질 수 있음 |
| 유지보수 | 이름 규칙을 잘 지키면 유지보수에 좋음 | 컴포넌트 단위로 관리하면 유지보수에 좋음 |
