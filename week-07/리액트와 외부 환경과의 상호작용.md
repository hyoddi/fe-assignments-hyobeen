# Ref

**ref(Reference) : 특정 DOM 요소나 컴포넌트를 직접 참조하기 위한 객체**

- 컴포넌트가 기억하고 싶은 정보를 저장하는 공간
- 값을 변경해도 리렌더링이 일어나지 않음

---

## UseRef

Ref 객체를 생성하는 React Hook

- 인자로 Ref 초기값 전달
- 반환값은 current 속성을 가진 객체

사용법

```jsx
import { useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
  };

  console.log("렌더링!");

  return (
    <>
      <h1>{count}</h1>
      <button onClick={handleClick}>증가</button>
    </>
  );
}
```

기존 State를 사용했던 코드는 → 누를 때마다 리렌더링! (App 함수 다시 실행)

- 해당 State가 선언된 컴포넌트 함수가 다시 실행
- 렌더링! → 이 콘솔에 계속 찍힌다!

```jsx
import { useRef } from "react";

function App() {
  const countRef = useRef(0);
  // { current: 초기값 } 형태의 Ref 객체를 생성 (한다고 생각해도 된다)

  const handleClick = () => {
    countRef.current++;
    console.log(countRef.current);
  };

  console.log("렌더링!");

  return (
    <>
      <h1>화면은 안 바뀜</h1>
      <button onClick={handleClick}>증가</button>
    </>
  );
}
```

- `countRef.current` 값은 변경된다
- 하지만 State가 변경된 것이 아니므로 React는 App 컴포넌트를 다시 실행하지 않는다.
- `렌더링!` 은 처음 한 번만 출력!

리렌더링 = 컴포넌트 함수 재실행

State처럼 값 저장은 되는데 목적이 다르다고 이해하면 될 거 같다

!image.png

- State : React가 관리하는 상태
- Ref : React가 화면 갱신용으로 관리하는 값이 아님
    
    → **컴포넌트가 기억하고 싶은 값을 저장하는 공간**
    

**useRef는 컴포넌트가 다시 렌더링되어도 값을 유지하면서, 값이 변경되어도 리렌더링을 발생시키지 않을 때 사용한다.** 

특히 DOM 요소를 직접 참조할 때 많이 사용..?

# Ref를 이용해 DOM 조작하기

React 철학 : DOM을 직접 건드리지 말고 State로 화면을 관리하자!

→ 직접 건드릴 일이 거의 없지만, 가끔은 직접 접근해야 할 때가 있음

→ "화면에 무엇을 보여줄지"가 아니라 **"브라우저에게 특정 행동을 시켜야 하는 경우”**

| State로 가능 | Ref 필요 |
| --- | --- |
| 텍스트 변경 | 포커스 |
| 버튼 표시/숨김 | 스크롤 이동 |
| 색상 변경 | 비디오 재생 |
| 목록 추가 | 요소 크기 측정 |

**브라우저의 DOM API를 호출하여 특정 동작(포커스, 스크롤, 재생 등)을 수행할 때 사용!!**

---

코드 예제

```jsx
import { useRef } from "react";

function App() {
  // Ref 객체 생성
  // 렌더링이 다시 일어나도 동일한 객체를 유지
  const inputRef = useRef(null);
  const divRef = useRef(null);

  return (
    <div>
      <div>
        {/* input DOM 요소를 inputRef와 연결 */}
        <input ref={inputRef} /> // 렌더링 후 React가 해당 DOM 요소를 ref.current에 자동으로 할당

        <button
          onClick={() => {
            // Ref 객체 확인
            console.log(inputRef);

            // 실제 input DOM 객체의 focus() 호출
            // => 입력창에 커서 이동
            inputRef.current.focus();
          }}
        >
          입력창 포커싱 하기
        </button>

        <button
          onClick={() => {
            console.log(divRef);

            // 실제 div DOM 객체의 scrollIntoView() 호출
            // => 해당 요소 위치로 자동 스크롤
            divRef.current.scrollIntoView();
          }}
        >
          컨텐츠로 스크롤 하기
        </button>
      </div>

      {/* 스크롤이 생기도록 큰 영역 생성 */}
      <div
        style={{
          height: 1000,
          backgroundColor: "green",
        }}
      />

      {/* 이동 목표 지점 */}
      <div
        ref={divRef}
        style={{
          backgroundColor: "lightblue",
        }}
      >
        스크롤로 이동하고 싶은 컨텐츠
      </div>
    </div>
  );
}

export default App;
```

# Effect & Life Cycle

## Effect

렌더링 결과를 바탕으로 외부 환경과 상호작용하는 코드

- 렌더링 완료된 후 실행되는 후처리 작업
- API 호출, 이벤트 리스너 등록 등 외부 환경과의 상호 작용

예시)

- 서버 API 호출
- 타이머 등록
- DOM 조작
- 브라우저 제목 변경
- 이벤트 리스너 등록

### 왜 Effect가 필요할까?

컴포넌트는 생명주기(Life Cycle)를 가진다

```
Mount ->  Update ->  Update -> ... -> Unmount
```

그런데 개발자는 가끔

- 컴포넌트 생성될 때 API 호출하고 싶은데?
- 컴포넌트 제거될 때 타이머 정리하고 싶은데?
- count가 바뀔 때 서버 요청 보내고 싶은데?

그래서 React가 제공하는 기능

UseEffect() : 렌더링이 완료된 후 실행되는 Effect를 등록하는 Hook

- Mount 시 실행 가능
- Update 시 실행 가능
- Unmount 시 실행 가능

```jsx
import { useEffect, useState } from "react";

function App() {
  const [count, setCount] = useState(0);

  // Mount, Update 시 컴포넌트 함수 재실행
  console.log("렌더링");

  useEffect(() => {
    // 1. 최초 Mount 후 실행
    // 2. count가 변경되어 Update 될 때마다 실행
    console.log("Effect 실행");

    return () => {
      // 1. count가 변경되어 Effect가 다시 실행되기 직전 실행
      // 2. 컴포넌트가 Unmount 되기 직전 실행
      console.log("Cleanup 실행");
    };
  }, [count]);
  // count를 의존성으로 등록
  // count가 변경될 때마다 Effect 재실행

  return (
    <>
      <h1>{count}</h1>

      <button onClick={() => setCount(count + 1)}>
        증가
      </button>
    </>
  );
}

export default App;
```

## Component 생명 주기

컴포넌트가 생성되고, 변경되고, 사라지는 과정

!image.png

### 1. Mount

컴포넌트가 처음 화면에 렌더링되는 단계

```jsx
function App() {
	return <h1>Hello</h1>;
}
```

**화면에 처음 나타나는 순간**

### 2. Update

State 또는 Props가 변경되어 컴포넌트가 다시 실행되는 단계

```jsx
setCount(count + 1);
```

**App() 재실행 → 리렌더링**

### 3. Unmount

컴포넌트가 화면에서 제거되는 단계

타이머 예제를 보자

```jsx
import { useEffect, useState } from "react";

function Timer() {
  useEffect(() => {
    console.log("타이머 시작");

    const timer = setInterval(() => {
      console.log("1초 경과");
    }, 1000);
    // setInterval은 js 기본 제공 함수
    // 1000ms 마다, 익명함수 반복 호출!
    
    

    // 컴포넌트가 제거될 때 실행
    // useEffect의 반환 함수(return)
    **// Cleanup Function**
    return () => {
      console.log("타이머 종료");
      clearInterval(timer); // 타이머 정리(clearInterval)
    };
    // 이거 없으면 컴포넌트가 사라져도 타이머가 계속 돌아간다!
    // 따라서 컴포넌트가 **Unmount될 때 타이머를 정리해야 한다!**
    
    
  }, []);

  return <h1>타이머 동작 중</h1>;
}

export default function App() {
  const [show, setShow] = useState(true);

  return (
    <>
      <button onClick={() => setShow(!show)}>
        타이머 토글
      </button>

      {show && <Timer />} // **show === true 일때만 렌더링해라!**
      // 1. Timer() 컴포넌트를 화면에 추가(Mount)
			// 2. useEffect 실행 → 타이머 시작
    </>
  );
}
```

`true → false`로 바뀌는 순간 `Timer`가 언마운트되고, React가 Cleanup Function을 자동으로 실행

**컴포넌트가 보이지 않는다고 해서 반드시 Unmount 되는 건 아니다!**

 **React 렌더링 트리에서 제거될 때 Unmount가 발생**

## 클래스 컴포넌트와 함수형 컴포넌트의 생명 주기

예전 React에서는 클래스 컴포넌트에서 라이프사이클 메서드를 사용했다.

```jsx
class MyComponent extends React.Component {
  componentDidMount() { // 이렇게 적으면 React가 알아서 함수 마운트 시에 실행해줌
    console.log("마운트 완료");
  }

  componentDidUpdate() {
    console.log("업데이트");
  }

  componentWillUnmount() {
    console.log("언마운트");
  }

  render() {
    return <div>Hello</div>;
  }
}
```

→ 이게 대체 뭐냐,

옛날 리액트는 컴포넌트 만들 때 지금처럼 함수형 컴포넌트가 아니라,  `React.Component` 클래스를 상속받아 클래스로 컴포넌트를 작성했대요..
